# AWS deployment (Terraform)

Deploys the **Java** service and PostgreSQL to AWS, sized to stay inside the
AWS Free Tier.

```
client ──HTTPS──▶ CloudFront ──HTTP:80──▶ EC2 t3.micro (Docker: truestate-java)
                  (free TLS,               │  public subnet, SG allows only
                   no caching)             │  CloudFront's IP ranges
                                           ▼
                                 RDS PostgreSQL 16 db.t4g.micro
                                 private subnets, SG allows only the app
```

| Piece | Why this and not something else |
|---|---|
| EC2 + Docker | Free-tier eligible. ECS Fargate and App Runner have no free tier, and Fargate would also need a load balancer. |
| RDS PostgreSQL | A managed database (backups, patching) on the free-tier micro class. |
| CloudFront | Gives a free HTTPS URL. An Application Load Balancer costs about $16/month. |
| No NAT gateway | That would cost about $32/month. The instance uses its public IP for outbound traffic, and the database needs no internet access. |
| SSM instead of SSH | No key pair and no open port 22. Deploys and shell access go through IAM and are logged. |
| GitHub OIDC | The deploy job gets short-lived credentials. No AWS access keys are stored anywhere. |
| DB password | Generated by Terraform as an *ephemeral* value and written to RDS and to SSM Parameter Store (free tier) through write-only arguments, so it is never in the repo, in Terraform state, or in GitHub. |

## What it costs

These are us-east-1 on-demand list prices. Check your own account's
**Billing → Free Tier** page; it is the source of truth.

| Resource | Free-tier allowance | If not covered |
|---|---|---|
| EC2 t3.micro | 750 h/month | ~$7.60/month |
| EBS 30 GB gp3 (root disk) | 30 GB | ~$2.40/month |
| Public IPv4 address | 750 h/month | ~$3.60/month |
| RDS db.t4g.micro, single-AZ | 750 h/month | ~$11.70/month |
| RDS 20 GB gp2 + backups | 20 GB + backups up to DB size | ~$2.30/month |
| CloudFront | 1 TB and 10M requests/month, always free | pennies |
| SSM Parameter Store (standard) | always free | — |
| S3 state bucket | a few KB | < $0.01 |
| **Total** | **about $0** | **about $28/month** |

Which free tier applies depends on when the AWS account was created:

- **Created on or after 15 July 2025: the Free plan.** You get credits (up to $200)
  for 6 months, and nothing is charged until they run out or you upgrade.
- **Created earlier: the legacy 12-month free tier.** It covers the allowances
  in the table during the account's first year.

Either way, set a budget alert: **Billing → Budgets → Create budget →
"Zero spend budget"**.

**The quickest way to spend money by accident is to leave this running after
your free tier ends.** When you are done, destroy it (see below).

## First-time setup

You need the AWS CLI logged in as an administrator of your account
(`aws login` or `aws configure`). Then run:

```bash
# 1. State bucket (once)
cd infra/bootstrap
terraform init
terraform apply
BUCKET=$(terraform output -raw state_bucket)

# 2. The stack (takes ~10 minutes, mostly RDS and CloudFront)
cd ..
terraform init -backend-config="bucket=$BUCKET"
terraform apply
terraform output github_variables
```

3. Make the image public so the instance can pull it without credentials. On
   GitHub, go to **your profile → Packages → truestate-java → Package settings →
   Change visibility → Public**. (It is only the compiled app; the source
   repo is already public.)
4. Add the four values from `github_variables` as **repository variables**
   under **Settings → Secrets and variables → Actions → Variables**.
   They are not secrets: the role ARN alone grants nothing, because the role
   trusts only workflows on this repo's `main` branch.

From then on, every push to `main` that passes the tests runs the `deploy` job
in CI. That job:

1. builds the images;
2. assumes the deploy role through OIDC;
3. runs `/opt/truestate/deploy.sh sha-<commit>` on the instance through SSM;
4. smoke-tests `/health` and `/docs` through CloudFront.

Until those variables exist, the deploy job is skipped, not failed.

If your account already has a GitHub OIDC provider, apply with
`-var create_github_oidc_provider=false`.

## Operating it

```bash
# Shell on the instance (no SSH)
aws ssm start-session --target "$(terraform output -json github_variables | jq -r .AWS_INSTANCE_ID)"
sudo docker logs --tail 100 truestate-java

# First-boot log (Docker install, first deploy)
sudo cat /var/log/cloud-init-output.log
```

To rotate the database password, run `terraform apply -var db_password_version=2`,
then redeploy so the container picks up the new value.

## Tearing it down

```bash
cd infra
terraform destroy             # everything billable: EC2, RDS, CloudFront, VPC, IAM
cd bootstrap
terraform destroy             # the state bucket (do this last)
```

The RDS instance has `skip_final_snapshot = true` and no deletion protection,
so the destroy leaves no snapshot behind to bill you. Destroying CloudFront takes
a few minutes, because AWS disables the distribution before deleting it. Images
on GHCR are not affected.
